## Speech adapter API evaluation (Task 13)

The current capture path computes local RMS levels in `voice-capture.js` and calls `onSpeechStart` after its short threshold in `transport.ts`. That signal interrupts playback before a transcript is committed. The [official Scribe JavaScript client](https://elevenlabs.io/docs/eleven-api/resources/libraries/scribe-stt/javascript-scribe) now handles microphone capture/encoding and provides partial and committed transcript events. [Native mute/unmute](https://elevenlabs.io/docs/changelog/2026/5/13) and [self-hosted worklets](https://elevenlabs.io/docs/changelog/2026/8/17) close two earlier gaps. Its documented realtime events do not expose the same local RMS speech-start signal; server [VAD](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/transcripts-and-commit-strategies) commits after detecting speech and silence. This last comparison is an inference from the documented API, not a measured SDK trial.

No Scribe SDK code was installed, wired into the app, or benchmarked. Keep the current adapter based on this API evaluation. Revisit with a code trial if the SDK can preserve immediate local interruption, mute/reconnect and transcript behavior with less owned code. Evaluate text-to-speech separately; Scribe is a transcription client.
