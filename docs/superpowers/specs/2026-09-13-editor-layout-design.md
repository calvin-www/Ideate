# Optional editor layouts

Navigation update: the per-page restoration rules below are superseded by [Desk and tool interaction design](../../interaction-design.md). Desk objects and tool shortcuts now open one tool; the previous global arrangement is restored explicitly through Layout. The stable editor-host and output-preservation requirements still apply.

Approved in the conversation: the existing desk, navigation, single-editor view, and optional Study Partner sidebar remain the default. Editors can optionally be split horizontally or vertically, rearranged into tab groups, resized, or floated above another editor. A floating Python editor contains the existing editor, execution controls, and output. Maximize fills the editor workspace; restore recovers the previous layout including floating bounds. Separate browser popouts are a follow-up.

Use Dockview for docking, tab groups, split resizing, and floating windows. Keep editor React trees in stable portal containers outside Dockview's component lifecycle, so rebuilding a layout never resets editor undo/history. Keep the Python runner and collaborator at shell scope. A small layout controller owns arrangement, commands, visibility, and saved layout; document content remains in the existing workspace store. Focus and visibility are distinct: several tools can be visible, one is the current tool for shortcuts and AI context.

The Layout menu offers split beside/below, float an editor, restore saved arrangement, single-editor view, and reset. Group controls expose float/dock, maximize, and hide. Hidden editors retain data. Each header page starts with its own full-size editor and remembers an independent arrangement. Switching away and back restores that page automatically, including after a reload. The selected header page is separate from the focused editor, so interacting with a pane does not transfer the arrangement to another page. Single editor and Reset affect only the selected page; Single editor retains its arrangement for explicit restoration. Closing the final editor returns that page to the default view. Launch still opens the desk. Versioned page preferences validate each layout independently and migrate the legacy global preference to its first editor's page. Transient maximization is not persisted. Narrow viewports temporarily use the single-editor view without overwriting the desktop arrangements. Floating bounds stay within the workspace.

Match the existing sage/cream colors, compact system typography, thin separators, and quiet buttons. Only advanced layouts show docking headers; the default view keeps its existing toolbars.

Python Output follows the same arrangement model as an optional fourth panel. Its Move output control places it left, right, above, below, in a tab with the source, or in a floating window. Returning output to the editor restores the default embedded area. A stable output portal preserves its displayed run, selection, Clear state, and streaming updates. Output remains associated with Python for context while source visibility is tracked separately. Error links and Study Partner Show actions reveal a hidden source editor. Existing saved layouts with three editors remain valid.

Run the existing unit suite, typecheck, production build, and relevant editor regressions.
